## Contrat commun

- **next-intl sans routage localisé** : aucune URL ne change, aucun `[locale]`, aucun `/fr`.
- Au rendu, un cookie valide fait foi : aucun appel profil ni vérification Auth supplémentaire dans `getLocalePreference`. Sans cookie valide, un utilisateur connecté retrouve sa préférence profil ; sinon Accept-Language > pays Cloudflare fiable > anglais. La langue du propriétaire d'une carte ou d'un profil public n'intervient jamais.
- Accept-Language : poids q, sous-tags en-GB/fr-CA, ordre stable à égalité, q=0 exclu, entrée bornée et invalide ignorée. Les pays ne supplantent jamais une langue supportée du navigateur. Un refus explicite du français exclut aussi son repli pays.
- Pays FR : **MA, DZ, TN, FR, BE, LU, MC, SN, CI**, sans CH ni CA. `I18N_TRUST_CF_COUNTRY=false` par défaut. Ne l'activer qu'après preuve que l'origine n'est accessible que par le chemin Cloudflare de confiance ; aucune hypothèse tirée de l'existence d'un simple en-tête. Pas de service externe de géolocalisation.
- Flag `NEXT_PUBLIC_I18N_ENABLED=false` par défaut (à la construction). Off : anglais existant, sélecteur et bandeau absents, aucune RPC/cookie i18n supplémentaire. Aucun changement Coolify ni déploiement pendant la PR.
- Sélecteur natif partagé Automatic / English / Français dans navigation desktop/mobile, paramètres, login/signup/forgot/reset. Server Action validée + `router.refresh()`, sans rechargement document ni clé React liée à la locale. Conserver pack ouvert, cartes révélées, filtres, saisies, modales et scroll.
- Cookie `yokkai_locale`, un an, HttpOnly, Secure en production, SameSite=Lax, Path=/, sans Domain. Format versionné `v1:auto|manual:en|fr:new|seen`. Cookie invalide : redétection. Mode auto mémorisé, bannière fermée mémorisée uniquement ici. Le cookie survit à la déconnexion.
- Bandeau à la première détection automatique non anglaise : « Site affiché en français · Switch to English ». Un clic change la langue ; une fermeture empêche son retour. Le choix explicite est mémorisé, la détection n'écrit jamais de préférence en base.
- Première réponse HTML et hydratation avec la même langue ; pas de détection tardive par `navigator.language`. Configuration par requête, aucune variable mutable globale de locale. Le résolveur serveur est mémorisé par requête.
- Exception de panne racine déjà identifiée dans le plan : `global-error` dispose de son propre fournisseur minimal et garde un secours anglais déterministe lorsque le layout/résolveur de requête a échoué. Il ne tente pas de redétecter le navigateur après hydratation. Les erreurs de route ordinaires utilisent la locale active.
- Préserver les cookies Auth, `setAll` et `private, no-store`. Le proxy Supabase ne contient aucun appel `get_my_locale` ; ses renouvellements et en-têtes Auth restent ceux de master. Une panne de RPC locale ne fait pas échouer une authentification.
- `/share/[id]` conserve son contournement du renouvellement Auth dans le proxy. HTML/RSC personnalisés sans cache partagé ; images de partage et OG anglaises invariantes, sans cookie ni locale dans leur clé de rendu. Ne modifier aucun renderer/cache d'image dans cette tranche.
- Dates : UTC en base, fuseau du navigateur pour l'affichage, même rendu initial serveur/client. Pour resets et échéances, compte à rebours, jamais une heure fixe ni « heure de Paris » / « Paris time » joueur. La configuration i18n fixe UTC comme valeur SSR sûre ; les futures dates absolues seront formatées après montage avec le fuseau navigateur.
- Le fil d'accueil traduit dans PR 1 affiche un repère neutre pendant le SSR puis ses dates historiques dans la locale et le fuseau du navigateur, après hydratation, lorsque le flag est actif. Flag off, le format historique est conservé. Cela ne change aucun reset ni aucune échéance métier.
- Anglais source + français dans la même PR pour tout nouveau texte joueur. Clés sémantiques camelCase, interpolation et pluriels ICU, aucune concaténation de phrase. Les contenus saisis par des joueurs ne sont pas traduits.
- **Intangibles** : noms de cartes/personnages/licences/catégories, images, raretés C/R/SR/SSR/LR/Shiny, Karas, Regular Pack / Decision Pack, rendus et animations, taux, tables cards/collection et RPC de tirage. Dans les fichiers mixtes autorisés : seuls textes → `t(...)`, import et initialisation du traducteur ; valeurs de données passées en paramètres ICU sans les changer. Tout autre changement dans ces fichiers nécessite un arrêt.

## Profil : migration proposée, non appliquée

`supabase/migrations/20261027001000_profile_locale.sql` ajoute `public.user_profiles.locale text DEFAULT NULL`, CHECK NULL/en/fr, sans backfill ni grant SELECT/UPDATE direct. NULL signifie automatique, sans écraser le cookie.

RPC `get_my_locale()` et `set_my_locale(p_locale text)` : SECURITY DEFINER, search_path vide, identité exclusivement `auth.uid()`, pas de cible user_id, EXECUTE seulement authenticated ; PUBLIC/anon/service_role révoqués. Setter limité à sa propre ligne, valeurs invalides et profil absent refusés. La policy de lecture existante ne justifie aucun nouveau grant de colonne.

Connexion, inscription avec session et `/auth/confirm` : profil explicite reflété dans le cookie avant la redirection. Déconnexion : garder le cookie sans lire le profil. Aucun appel de synchronisation n'écrit le profil. Le choix connecté écrit d'abord la RPC, puis le cookie ; une erreur conserve l'ancienne préférence et affiche un message sûr.

**Ne pas appliquer cette migration pendant la PR. Walid la passera séparément via `scripts/deploy-migrations.sh`.** Ne pas activer la persistance connectée avant son déploiement. Les tests SQL de droits/replay relèvent de la CI isolée.

## Erreurs Auth ambiguës

Le code seul est utilisé lorsqu'il est suffisant ; on ne compare jamais nos propres textes traduits.

- GoTrue **`over_email_send_rate_limit`** désigne à la fois le budget d'envoi global et le cooldown d'une adresse. Le préfixe serveur fixe `For security purposes, you can only request this ` distingue le cooldown. Les clés sont `authErrors.emailLimit` et `authErrors.emailCooldown` ; un éventuel `after N seconds` est extrait, borné à six chiffres, passé comme paramètre ICU `seconds`. Sans délai exploitable, clé générique `rateLimit`.
- **`unexpected_failure`** (ou erreur 5xx) couvre plusieurs pannes. Les seuls messages fixes `Error sending confirmation email` et `Error sending recovery email` identifient la livraison SMTP ; clé `emailUnavailable`, sinon repli générique. Aucun détail fournisseur, adresse, jeton ou diagnostic brut n'est affiché.
- Le cooldown anglais garde exactement son texte antérieur, même quand GoTrue fournit N ; le français peut exploiter le délai. Les états conservent clé et paramètres pour être retraduits après un changement de langue.

### Lecture du profil et export après revue

Le profil n’est lu qu’à une connexion (y compris OAuth et une inscription qui ouvre une session), à `/auth/confirm`, ou pour un utilisateur connecté dont le cookie de langue est absent/invalide. Le proxy principal récupère alors cette préférence et écrit le cookie avant le rendu ; le résolveur serveur garde le même repli lorsqu’il est appelé directement sans cookie. Le chemin normal avec cookie valide ne crée aucun client Supabase dans le résolveur et ne fait aucune RPC locale dans les deux proxies. `set_my_locale` écrit toujours le profil puis le cookie. Une déconnexion conserve le cookie sans RPC locale.

La migration contient désormais un `CREATE OR REPLACE FUNCTION public.build_data_export_without_wall_interactions` complet et explicite : même corps que le builder initial, avec le seul champ `'locale',t.locale` dans la projection de profil. Aucun `pg_get_functiondef`/`replace()` dynamique ; propriétaire, ACL, snapshot stable, réservation et limites existantes conservés. Les tests d’export restent inchangés.
